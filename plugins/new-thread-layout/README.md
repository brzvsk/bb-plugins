# Project Home

Turns BB's New thread screen into the project's home, and names the project in the top bar.

On the New thread screen (wide layout):

- with a project selected, the composer sits at the bottom like a thread's and the list above it scrolls away underneath: **Pinned**, then **Running** (root threads where an agent works in the thread itself, in background work, or in any descendant thread), then **Idle** (the other unarchived root threads; both by threads that need you first, then recency; the second line is the newest thing said in the thread: the author's turn as "You: …", the agent's reply as plain text, or its thinking in italics; a thought or reply still streaming is pieced together from its deltas; tool steps and bb's "[bb system]" notices are skipped, and running threads refresh it every 3 s. An unsent composer draft takes the second line instead, messenger style: "Draft:" in red, then the draft's first line (read from bb's per-window `bb.promptbox.contents-…` storage when the thread list reports a draft), child threads counted). No cards. A read, idle thread bound to an automation leaves Idle and returns when it is busy, unread or needs you.
- a fixed zone right under the top bar, outside the scrolling list, switches between **Scheduled** and **Recently done** (the choice is remembered; a tab with nothing in it is not offered). Scheduled: every upcoming enabled automation of the project, one line each with the thread it runs in (muted; "new thread" for per-run automations) and the next run on the right; a bound line opens its thread; paused automations follow at the end marked Paused; on hover a line offers the bound thread's Mark read/unread and Pin/Unpin (pinning brings it into attention), Pause or Resume, and Open automation; lines are dimmed unless their thread has something unread, then full strength with bb's unread dot instead of the clock. Recently done: root threads archived in the last 48 hours, as thread rows. The zone scrolls on its own past a few rows. On wide screens its tabs sit in the top bar's row, beside the project name.
- the project name at the top-left of the screen, where a thread's header row sits; clicking it returns to the project (reselects it in the composer). In the macOS desktop app, where bb lifts every page header into the window's own row (traffic lights, back, forward, sidebar toggle), the name sits in that row too, centered on the traffic lights: after the window controls when they lie over the card, else at the card's inset, so it does not jump between a thread and the project home.
- without a project, the original layout: the composer in the lower middle under a "Working on" heading whose project opens BB's own project dropdown (the native chip under the composer stays visible and works as before).

The home of all projects is the New thread screen with bb's personal project ("No project"): a home icon left of the project name (top bar, thread headers, maximized panel) goes there, and a two-finger swipe right on a project's New thread screen does too. There the top bar lists the projects after the home icon, like tabs, in the thread list's order and without the projects hidden there: quiet by default, a blue dot when something in the project is unread, full strength when something waits for you, a shimmer while an agent works there; a click opens the project. The board below lists threads and automations without a project. The project tabs show only at home.

In every thread's header row, the project name precedes the title as a link; clicking it opens the project (the New thread screen with that project selected).

With the right panel maximized bb hides the thread header; the same high-level navigation (project / thread title / ⋯ with bb's thread menu) then leads the panel's tab strip, followed by a separator, and disappears again when the panel is restored.

On a thread, a two-finger trackpad swipe right over the timeline goes back to the project's home, like Chrome's back swipe (gesture and arrow ported from browser-gestures): a dark arrow slides in from the timeline's left edge, lifting with it fully out navigates, pulling back cancels. Horizontal scrollers inside the timeline (wide code blocks) keep the swipe until they reach their left edge; vertical scrolls, swipes left and modifier keys are ignored. A finger held completely still commits after about 0.6 s, since a page cannot see fingers lift.

Data comes from bb's sidebar thread view (active and archived lifecycles), the bundled Automations plugin's `automations_list` RPC, and `threads.events.list` (newest turn-request and item events) for the second line (a few at a time, refetched when a thread's `updatedAt` changes). No server code, settings or storage.

Uses BB DOM attributes (`root-compose-main-panel`, `root-compose-compact-home`, `data-promptbox-project-control`, `app-page-header-content-row`, `thread-detail-timeline-panel`); future BB layout changes may require an update. The compact (mobile) home is unchanged. The homepage slot's `projectId` is null on the plain compose route, so the board reads the composer's selected project.

Build: `npm ci --include=dev --ignore-scripts`, `npm run typecheck`, `npm test`, `npm run build`. Install from the repository root: `bb plugin install . --plugin new-thread-layout`.
