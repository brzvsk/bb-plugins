# Project Home

Turns BB's New thread screen into the project's home, and names the project in the top bar.

On the New thread screen (wide layout):

- with a project selected, the composer sits at the bottom like a thread's and the list above it scrolls away underneath: **Pinned**, then **Running** (root threads where the agent's turn is in progress, in the thread, a background agent, a workflow or any descendant thread; a background command left after the turn, such as a CI watch, does not count: the thread then waits quietly with bb's background glyph (a pinned one keeps shimmering) and stays out of Waiting for you even if its reply is unread, until the agent wakes again), then **Idle** (the other unarchived root threads; both by threads that need you first, then recency; the second line is the newest thing said in the thread: the author's turn as "You: …", the agent's reply or its thinking after the thread's provider mark (Anthropic, OpenAI, …) in monochrome; a thought or reply still streaming is pieced together from its deltas; tool steps and bb's "[bb system]" notices are skipped, and running threads refresh it every 3 s. An unsent composer draft takes the second line instead, messenger style: "Draft:" in red, then the draft's first line (read from bb's per-window `bb.promptbox.contents-…` storage when the thread list reports a draft), child threads counted). No cards. A thread an automation runs in lives under Scheduled and joins the lists only when something happens there (working, unread, waiting for you) or you are involved (pinned, a draft, or your own message in the last two hours; automation prompts "[bb automation due:…]" do not count). With no other status, its left slot then shows a clock (next run and automation in its tooltip).
- a fixed zone right under the top bar, outside the scrolling list, switches between **Scheduled** and **Last week** (it opens on Scheduled; choosing Last week drops it over the lists below as a tall panel for scanning the archive, folded back by the tab again or Escape; a tab with nothing in it is not offered). Scheduled: every upcoming enabled automation of the project, one line each with the thread it runs in (muted; "new thread" for per-run automations) and the next run on the right; a bound line opens its thread; paused automations follow at the end marked Paused; on hover a line offers the bound thread's Mark read/unread and Pin/Unpin (pinning brings it into attention), Pause or Resume, and Open automation; lines are dimmed unless their thread has something unread, then full strength with bb's unread dot instead of the clock. Recently done: root threads archived in the last 48 hours, as thread rows. The zone scrolls on its own past a few rows. On wide screens its tabs sit in the top bar's row, beside the project name.
- the project name at the top-left of the screen, where a thread's header row sits; clicking it returns to the project (reselects it in the composer). In the macOS desktop app, where bb lifts every page header into the window's own row (traffic lights, back, forward, sidebar toggle), the name sits in that row too, centered on the traffic lights: after the window controls when they lie over the card, else at the card's inset, so it does not jump between a thread and the project home.
- without a project, the original layout: the composer in the lower middle under a "Working on" heading whose project opens BB's own project dropdown (the native chip under the composer stays visible and works as before).

The home of all projects is the New thread screen with bb's personal project ("No project"): a home icon left of the project name (top bar, thread headers, maximized panel) goes there, and a two-finger swipe right on a project's New thread screen does too. There a row of project chips sits right above the composer, in the thread list's order and without the projects hidden there (the top bar keeps only the home icon): quiet by default, a blue dot when something in the project is unread, full strength when something waits for you (running work shows in Running now, not on the chips); a click opens the project. A "+" at the end opens the projects hidden in the thread list (its "More"). Below them the home screen is an overview across those projects: **Pinned — focused on now** (pins are what you work on right now: the count turns orange at 3–4 pins and red above 4; pinned threads from every shown project and home, in pin order, showing their state in their row and not repeated below), **Waiting for you** (unread threads and agents asking, from every shown project), **Running now** (threads where an agent works, in the thread or below it), **Continue where you left off** (other unarchived threads with activity in the last two hours: where work was left off), each with the project's name muted before the title; then **Without a project** with the home's own threads. Quiet idle threads stay inside their projects. Scheduled and Last week at home cover every shown project plus home; Scheduled lists the next runs of every shown project (hidden projects left out) with the project's name, plus home's paused automations. The project tabs show only at home.

In every thread's header row, the project name precedes the title as a link; clicking it opens the project (the New thread screen with that project selected).

With the right panel maximized bb hides the thread header; the same high-level navigation (project / thread title / ⋯ with bb's thread menu) then leads the panel's tab strip, followed by a separator, and disappears again when the panel is restored.

On a thread, a two-finger trackpad swipe right over the timeline goes back to where the thread was opened from: the home screen when opened from home, otherwise the project's home (remembered per window), like Chrome's back swipe (gesture and arrow ported from browser-gestures): a dark arrow slides in from the timeline's left edge, lifting with it fully out navigates, pulling back cancels. Horizontal scrollers inside the timeline (wide code blocks) keep the swipe until they reach their left edge; vertical scrolls, swipes left and modifier keys are ignored. The destination rides beside the arrow as a pill (the home icon with "Home", or the project's name), so it is clear where the swipe goes before the fingers lift. A finger held completely still commits after about 0.6 s, since a page cannot see fingers lift.

Data comes from bb's sidebar thread view (active and archived lifecycles), the bundled Automations plugin's `automations_list` RPC, and `threads.events.list` (newest turn-request and item events) for the second line (a few at a time, refetched when a thread's `updatedAt` changes). No server code, settings or storage.

Uses BB DOM attributes (`root-compose-main-panel`, `root-compose-compact-home`, `data-promptbox-project-control`, `app-page-header-content-row`, `thread-detail-timeline-panel`); future BB layout changes may require an update. The compact (mobile) home is unchanged. The homepage slot's `projectId` is null on the plain compose route, so the board reads the composer's selected project.

Build: `npm ci --include=dev --ignore-scripts`, `npm run typecheck`, `npm test`, `npm run build`. Install from the repository root: `bb plugin install . --plugin new-thread-layout`.
