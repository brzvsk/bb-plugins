---
name: sidebar-focus
description: Explain or troubleshoot the Sidebar Focus plugin, which focuses BB's sidebar on one group and splits each group into In progress, Scheduled (automation threads with a clock and next run time) and Done (threads archived in the last 48 hours).
---
Sidebar Focus changes BB's built-in thread list without replacing it.

Focus: every top-level group header (project, Pinned, Threads, custom section, machine) gets a 12px crosshair button right after its collapse chevron, in the chevron's tones and hover-only like it (on a header without a chevron it ends the title). Pressing it hides every other group and the More overflow with CSS; the pressed button stays visible in the header and unfocuses on the next press. Focus changes run as a view transition (`transition.ts`): scoped to `[data-sidebar="content"]` when `Element.startViewTransition` exists, else a document transition naming only groups in view; each top block gets a temporary `view-transition-name` with class `sidebar-focus`; skipped under `prefers-reduced-motion`. Focusing a collapsed group expands it by clicking bb's own chevron and remembers that in `sidebar-focus:expanded-by-focus`; leaving that focus folds it back only if it is still expanded. The choice is per window in `localStorage` key `sidebar-focus:focus`; a focus whose group no longer exists shows everything.

Automations: the server RPC `automationThreads` reads the built-in `automations` plugin's `automations_overview` (target thread, else `lastRunThreadId`, enabled only) plus thread read state, refreshed every minute and on window focus. The content script marks the native `[data-sidebar-windowed-item]` wrapper of such a thread with `data-sidebar-focus-tucked` while its row has no `[data-sidebar-thread-trailing-indicator]`; its list becomes a flex column so tucked wrappers go last under an 11px "Automations N ›" disclosure (count before the chevron) (`closed` collapses them to zero height). Rows are never copied or moved in the DOM, so they keep every native detail. Open state is per group key in `localStorage` `sidebar-focus:automations-open-groups`. The selected thread is held in the place it had when selected and stays visible in a collapsed group. A wrapper virtualized away keeps its last mark until it mounts again.

In progress: every non-pinned top group's own row list (the first `[data-sidebar-windowed-item]` parent, else a plugin `.sidebar-focus-empty-list` after the header) gets an 11px "In progress N" label ordered first; with no untucked rows the count is dropped and a New Task row clicks the header's `New thread in …` button. Clock: `schedule.ts` prepends a clock plus the next run ("Today, 12:00", "Tomorrow, 9:00", "11 Nov, 22:00"; soonest `nextRunAt` among the thread's enabled automations) to `[data-sidebar-thread-trailing]` of every automation thread, with bb's `bb-sidebar-hover-actions-fade`; this replaces the retired automation-clock plugin.

Done (formerly Recently archived): server RPC `recentlyArchived` lists root threads (`hasParent: false`) archived in the last 48 hours, newest first, max 200; `unarchive` calls `bb.sdk.threads.unarchive`. Refreshed every minute, on window focus, and 400 ms after a row leaves bb's list. The content script draws its own rows for them (bb renders no archived rows while `threadLifecycles` is active only) at the end of the matching `project:` / `section:` group, else `threads`, in a `.sidebar-focus-archived` block ordered after tucked automations; collapsed per group (`archived:<group key>` in the same open set), opened while one of them is selected, absent in a collapsed group or when bb already lists any of them natively. A row click routes in-app via `history.pushState` + `popstate`; modifier clicks follow the link. Each row's ⋯ is bb's own `experimental_ThreadActionsMenu`, portaled into `.sidebar-focus-menu-slot` by `MenuBridge` (`menus.tsx`), a hidden component mounted as `experimental_threadHeaderAction` and `homepageSection` `menu-bridge` (that section is hidden by CSS); only the first mounted bridge renders, and outside thread and home screens the rows have no ⋯.

Enable or disable with `bb plugin enable sidebar-focus` / `bb plugin disable sidebar-focus`; disabling removes the style, buttons and block. It depends on `[data-bb-plugin="thread-list"]`, `[data-sidebar-visibility-group]`, `[data-sidebar-section-id]`, `[data-sidebar-sticky-tier="label"]`, `[data-sidebar-row-controls]`, `[data-sidebar-trailing-controls]`, `a[data-sidebar-thread-id]`, `.bb-sidebar-selected-row`, `[data-sidebar-windowed-item]`, `[data-sidebar-thread-trailing-indicator]` and `[data-testid="sidebar-thread-list-more-trigger"]`, so a BB sidebar change can stop it until it is updated.
